# Шаблоны проектов

Готовые каркасы, с которых начинается работа: не пустая папка, а структура, план, тесты и CI.
Всё в этом репозитории — примеры и заготовки. Клиентских данных, заказов и переписок здесь нет
и не будет.

Лицензия MIT: берите, меняйте, используйте в своих проектах и в работе с клиентами.

## Что внутри

| Папка | Что это | Когда брать |
|---|---|---|
| [`starter/`](./starter/) | базовка проекта: `AGENTS.md` для ИИ-агента, `docs/ПЛАН.md`, `docs/СДАЧА.md`, `docs/ТЗ.md`, `src/`, `tests/`, CI | любой новый проект |
| [`bot-aiogram/`](./bot-aiogram/) | каркас Telegram-бота: диалог по шагам, проверки ввода, SQLite, лимиты, белый список, systemd + nginx | боты на aiogram 3 |
| [`github-actions/`](./github-actions/) | два готовых workflow: тесты на push и проверка демо-страниц | подключить проверки за минуту |
| [`demo-page/`](./demo-page/) | шаблон демо-страницы: один файл, без внешних зависимостей, открывается с телефона | показать клиенту результат |

## Как пользоваться

**Вариант 1 — кнопка.** Сверху нажмите **Use this template → Create a new repository**.
Получите свой репозиторий с этой структурой, без истории коммитов.

**Вариант 2 — скачать одну папку.** Скачайте архив репозитория и возьмите нужную папку.

**Вариант 3 — скопировать файлы.** Например, только `starter/docs/ПЛАН.md` и `AGENTS.md`
в существующий проект.

## starter: базовка нового проекта

```
starter/
├── AGENTS.md          правила для ИИ-агента: что читать, как коммитить, когда остановиться
├── docs/ТЗ.md         что просит клиент — словами клиента
├── docs/ПЛАН.md       шаги по 1–3 часа, у каждого критерий «готово»
├── docs/СДАЧА.md      чек-лист приёмки: код, демо, передача
├── docs/ТОКЕН.md      куда вписать ключи и как проверить, что не утекли
├── src/ tests/        каркас кода и два зелёных теста
├── conftest.py        чтобы `from src.main import ...` работал
├── .gitignore         секреты и данные клиента не попадут в репозиторий
└── .github/workflows/ тесты на каждый push в main
```

Главная идея: правила и план записаны в файлах, а не в голове. Поэтому и человек, и любая модель
(Claude, Copilot, Codex) работают по одному и тому же плану, а не «как получится».

Проверить, что каркас живой:

```bash
cd starter
python -m venv .venv && . .venv/bin/activate
pip install -q pytest
python -m pytest -q        # 2 passed
```

## bot-aiogram: каркас Telegram-бота

```
bot-aiogram/
├── bot/core.py       логика без Telegram: состояния, проверки, SQLite
├── bot/limits.py     лимит сообщений и белый список на время показа
├── bot/app.py        aiogram 3: обработчики, клавиатуры, polling и webhook
├── bot/simulate.py   поговорить с ботом в терминале — токен не нужен
├── tests/            58 тестов без сети и без Telegram
└── deploy/           systemd, nginx, install.sh
```

Разделение намеренное: всё, что можно проверить тестами, живёт в `core.py`, а Telegram-слой тонкий.
Поэтому «бот отвечает не то» ловится за 0,1 секунды, а не после деплоя.

Потрогать без токена:

```bash
cd bot-aiogram
python -m bot.simulate
```

## github-actions: проверки на каждый push

| Файл | Что проверяет |
|---|---|
| `tests.yml` | `pytest` в корне и в каждой папке проекта, сводка в Actions |
| `demo-check.yml` | демо-страницы: незаменённые метки, внешние ресурсы, вес, viewport |

Кладите в `.github/workflows/` своего репозитория. На публичных репозиториях минуты Actions
бесплатны и не ограничены, на приватных — 2 000 минут Linux в месяц.

## demo-page: шаблон демо

Один HTML-файл, инлайновые стили, никаких CDN и шрифтов — поэтому открывается офлайн,
в предпросмотре и с телефона. Метки `%%ЗАГОЛОВОК%%`, `%%ДАННЫЕ%%` заменяются на реальные данные.

## Служебные файлы

`.gitignore` и `.github/workflows/tests.yml` — файлы, имя которых начинается с точки. При загрузке
через браузер GitHub их не видит, поэтому они создаются вручную: их содержимое целиком лежит в
[`docs/СЛУЖЕБНЫЕ-ФАЙЛЫ.md`](./docs/СЛУЖЕБНЫЕ-ФАЙЛЫ.md).

Переменные окружения бота описаны в [`bot-aiogram/ПЕРЕМЕННЫЕ.md`](./bot-aiogram/ПЕРЕМЕННЫЕ.md).

## Чего здесь нельзя найти

- ТЗ реальных заказов, переписку, контакты клиентов — этого не публикуем никогда;
- ключи, токены, `.env` — только `.env.example` с пустыми значениями;
- данные клиентов — в примерах только вымышленные записи.
