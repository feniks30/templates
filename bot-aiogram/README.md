# Демо-бот «Заявки» — рабочий прототип в Telegram

Живое демо вместо скриншота: клиент нажимает Start, оставляет заявку и сразу видит её в списке
со статусами. Данные тестовые, бот ничего не рассылает и не пишет первым.

Проверено: **58 тестов** без Telegram и без сети (`python -m pytest tests`).

## Что внутри

```
bot/core.py       логика: состояния диалога, проверки, SQLite — без Telegram
bot/limits.py     лимит сообщений и белый список на время показа
bot/app.py        aiogram 3: обработчики, клавиатуры, polling и webhook
bot/simulate.py   тренажёр: поговорить с ботом в терминале, без токена
tests/            core (41), limits (9), app (8)
deploy/           systemd, nginx, install.sh
```

Разделение намеренное: всё, что можно проверить тестами, живёт в `core.py`. Telegram-слой тонкий,
поэтому «бот отвечает не то» ловится за 0.1 секунды, а не после деплоя.

## 1. Посмотреть без Telegram и без токена

```bash
cd examples/демо-бот-заявки
python -m bot.simulate
```

Или проиграть готовый сценарий (удобно для записи демо клиенту):

```bash
python -m bot.simulate --script "Иван|нужен парсер цен конкурента|3 дня|Отправить|Мои заявки"
```

```
вы: 3 дня
бот: Проверьте заявку:
     Имя: Иван
     Задача: нужен парсер цен конкурента
     Срок: 2026-11-14
вы: Отправить
бот: Заявка №1 принята. Статус — «новая».
```

## 2. Запустить как настоящего бота (своя машина)

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # вписать BOT_TOKEN, остальное можно оставить
python -m bot.app             # polling — проще всего для проверки
```

Токен берётся у BotFather (`/newbot`). В чат его не присылать — он нужен только в `.env`,
который в `.gitignore`.

## 3. Выложить на сервер (webhook)

Пошагово, на `ubuntu@134.98.147.64`:

```bash
# 1. домен (без него Telegram не примет webhook: нужен https)
#    A-запись fh.example.com → 134.98.147.64

# 2. файлы бота
rsync -av --exclude .venv --exclude data ./ user@134.98.147.64:/tmp/bot-orders/

# 3. установка (создаст пользователя, venv, systemd; попросит заполнить .env)
ssh user@134.98.147.64 'cd /tmp/bot-orders && sudo ./deploy/install.sh'
ssh user@134.98.147.64 'sudo nano /etc/fh-bots/orders.env'   # BOT_TOKEN, WEBHOOK_BASE, WEBHOOK_SECRET
ssh user@134.98.147.64 'cd /tmp/bot-orders && sudo ./deploy/install.sh'

# 4. nginx и сертификат
ssh user@134.98.147.64 'sudo cp /tmp/bot-orders/deploy/nginx.conf /etc/nginx/sites-enabled/fh-bots.conf'
ssh user@134.98.147.64 'sudo nginx -t && sudo systemctl reload nginx'
ssh user@134.98.147.64 'sudo certbot --nginx -d fh.example.com'
```

После этого бот сам ставит webhook при старте. Проверка:

```bash
systemctl status fh-bot-orders
journalctl -u fh-bot-orders -n 30 --no-pager
# в Telegram: /start → диалог
```

Без домена вариант проще: `python -m bot.app` в `screen`/`tmux` (polling), но тогда при
перезагрузке сервера бот не поднимется сам, и это честно говорится клиенту.

## 4. Белый список на время показа

Пока показываешь демо одному человеку — ограничить доступ, чтобы бот не стал публичным:

```bash
# /etc/fh-bots/orders.env
ALLOWED_IDS=123456789            # id клиента (узнать: написать боту Userinfo Bot)
sudo systemctl restart fh-bot-orders
```

Пустой `ALLOWED_IDS` = открыто всем (так делаем, когда ссылка идёт в отклик).
После показа: `sudo systemctl stop fh-bot-orders` — одна команда.

## 5. Что показывает клиенту

| Шаг | Что видит клиент |
|---|---|
| `/start` | «Как вас зовут?» — бот сразу в деле, без меню-заглушки |
| имя короче двух букв | вежливая переспрос — видно, что бот проверяет ввод |
| задача из одного слова | «опишите подробнее» — видно валидацию, а не «принял всё» |
| срок «3 дня» / «неделя» / «позже» | понимает свободный текст, не заставляет выбирать из списка |
| «Отправить» → «Отправить» ещё раз | «эта заявка уже принята — номер 1» — идемпотентность |
| «Мои заявки» | список со статусами: новая / в работе / сделано |

## 6. Ограничения, которые не обходим

- бот не рассылает сообщения и не пишет клиентам первым;
- лимит 8 сообщений в минуту на пользователя — не даёт засыпать бота и упереться в лимиты Telegram;
- в базе только тестовые записи, персональные данные клиента не попадают;
- токен демо-бота ≠ токен клиентского: клиент позже заводит своего и вписывает сам.
