# Правила для ИИ-агента: {{NAME}}

Ты работаешь над проектом «{{NAME}}». Начало: {{DATE}}. Ниже — жёсткие правила, их не обходим.

## 1. Что прочитать до первой строчки кода

1. `docs/ТЗ.md` — что просит клиент. Словами клиента, не пересказом.
2. `docs/ПЛАН.md` — шаги и критерии «готово». Делаем **только текущий шаг**.
3. `README.md` — как запускается.
4. Тесты в `tests/` — что уже зафиксировано.

Если в ТЗ нет ответа на вопрос, от которого зависит код, — **остановись и спроси**, не выдумывай.

## 2. Как работать

- Один шаг плана = один коммит. Сообщение: `шаг 2: разбор CSV` — коротко и по делу.
- Сначала тест, потом код, если поведение новое. Тест должен падать до правки.
- `python -m pytest -q` зелёный перед каждым коммитом. Красные тесты не коммитим.
- Не переписывай работающее без причины: минимальная правка вместо «я тут всё улучшил».
- Не добавляй зависимости без записи в `docs/ПЛАН.md`, зачем она.
- Файлы длиннее 300 строк — сигнал разделить, а не дописывать.

## 3. Чего не делать

- Не коммитить `.env`, ключи, токены, дампы базы, данные клиента.
- Не ходить в сеть из тестов: тесты офлайновые, сеть подменяется фикстурами.
- Не менять публичные имена функций «для красоты» — на них завязаны тесты и клиент.
- Не удалять чужие комментарии и `TODO` — это чужая память о решении.

## 4. Когда останавливаться

Остановись и напиши отчёт, если:

- нужен доступ (ключ, домен, сервер), которого нет;
- шаг требует решения клиента (меняется поведение, которое он уже видел);
- тест падает по причине, которую нельзя исправить в этом шаге.

## 5. Формат отчёта в конце сессии

```
Сделано: …
Тесты: N passed (было M)
Не сделано и почему: …
Что нужно от человека: …
Следующий шаг: …
```
